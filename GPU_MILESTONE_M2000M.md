# GPU milestone: Quadro M2000M + Qwen3-4B WPC

Date: 2026-08-22

## Verified

- Qwen3-4B WPC variants were tested against the preserved source model copy:
  - v3 / 6-bit: ~3.0 GB — starts and generates coherent code.
  - v4 / 4-bit: ~2.0 GB — starts and generates coherent code.
  - v5 / 2-bit: ~1.1 GB — starts, but output is visibly degraded/gibberish.
- The 4-bit build is therefore the current practical candidate for a small GPU-resident dispatcher.
- The working source copy is stored outside the repository; model weights are not committed to GitHub.
- The NVIDIA Quadro M2000M was identified as compute capability `sm_50`.
- A relocatable CUDA 12.0 toolchain was prepared without installing it system-wide.
- The toolchain required an extracted GCC 12 alongside the system compiler.
- A minimal CUDA kernel was successfully compiled for `sm_50` to PTX:

```text
>>> ZBUDOWANE dla sm_50, 1093 bajtow <<<
// Generated by NVIDIA NVVM Compiler
// Cuda compilation tools, release 12.0, V12.0.140
.version 8.0
```

## What this proves

The machine can produce GPU code targeted at the Quadro M2000M, and the 4-bit Qwen artifact is small enough to fit in the available VRAM reported during testing.

## What is not yet proven

Compilation is not the same as execution. The minimal kernel still needs to be launched on the physical M2000M and checked for a correct result. After that, the WPC decoder can be moved onto the GPU and benchmarked.

## Next step

1. Execute the `sm_50` kernel on the M2000M and verify the returned result.
2. Port the WPC 4-bit decode path to CUDA.
3. Run a real Qwen3-4B v4 generation on the GPU.
4. Measure tokens/s, VRAM use, and CPU↔GPU transfer cost before changing the packing layout specifically for the GPU.

This milestone intentionally records only verified results. It does **not** claim that full Qwen inference is already running on the GPU.
